## 1. فهم المشروع

وصيتي تطبيق لحفظ رسائل نصية لأشخاص محددين وإعداد إرسالها بالبريد الإلكتروني بتاريخ معين أو عبر مفتاح الغياب أو تأكيد شاهد موثوق. يستهدف من يريد ترك كلمات شخصية أو ذكريات أو تعليمات لأحبائه، أو إعداد رسالة لمناسبة مستقبلية.

التقنيات الحالية محفوظة: Next.js 14 App Router، React 18، TypeScript، Tailwind، Tajawal، Lucide، NextAuth/Google، Prisma/PostgreSQL، Google Drive وResend. وصف وظائف الإرسال والبيانات مستخلص من الكود، مع تصحيح الادعاءات المخالفة له. التحليل السابق للتنفيذ في [UI-SEO-ANALYSIS.ar.md](UI-SEO-ANALYSIS.ar.md).

## 3. SEO وGEO

- Title وdescription وcanonical مستقل لكل صفحة عامة، وOpen Graph وTwitter Cards بصورة موجودة فعلياً.
- عنوان الموقع الحالي مصدره `SITE_URL` في `src/lib/site.ts`؛ تغييره لاحقاً يحدّث metadata وsitemap وrobots دون تعديل أسرار أو إعدادات المصادقة والبريد.
- H1 واحد لكل صفحة مفحوصة، وتدرج H2/H3، وروابط داخلية وHTML مقروء من الخادم. الصفحات التعريفية تُولد ثابتة؛ الرئيسية تُعرض من الخادم مع إبقاء فحص الجلسة الأصلي.
- بيانات منظمة WebApplication على الرئيسية فقط، بالميزات المثبتة. أزيلت التقييمات والأعداد والتشفير والأسعار والصور والروابط الاجتماعية غير المثبتة. لم تُضف مراجعات أو أسئلة منظمة بقصد الإيحاء بأهلية نتائج خاصة.
- noindex افتراضي في الجذر؛ الصفحات العامة المعتمدة وحدها تفعّل الفهرسة. الدخول ومسودة الشروط وحالات التأكيد والخطأ لا تفهرس. لوحة المستخدم والإدارة ترث noindex وتبقى محمية بالمصادقة الأصلية. API واللوحة والإدارة مستبعدة من crawl ومن sitemap؛ robots ليس وسيلة حماية أو ضمان إزالة URL مفهرس سابقاً.
- تعريف الخدمة والميزات والقيود والأسئلة متاحة في HTML. لا يوجد وعد بأن ذلك يضمن ترتيباً أو توصية من محركات البحث أو أنظمة الذكاء الاصطناعي.

المرجع الفني: [Next.js 14 Metadata](https://nextjs.org/docs/14/app/api-reference/functions/generate-metadata)، و[Google: noindex](https://developers.google.com/search/docs/crawling-indexing/block-indexing). لا يجدر حجب `/login` عن crawl إذا أردنا قراءة noindex منه؛ الحسابات تظل محمية بالمصادقة.

لاحقاً بعد اعتماد الإصدار والنشر يدوياً: تأكيد الفرع المنشور وظهور الرئيسية للزائر، ثم إرسال sitemap إلى Search Console وBing وفحص canonical والفهرسة. يلزم اعتماد بريد دعم عامل وهوية المشغّل والسياسات النهائية. مسودة الشروط مستبعدة من sitemap عمداً حتى اعتمادها.

## 4. تجربة المستخدم والوصول

هوية عربية بالألوان الدافئة الموجودة أصلاً، مع عنوان يشرح الكتابة وموعد الوصول، وقسم مرئي يوضح رحلة الرسالة وموسوم بأنه تصور توضيحي. زر الدخول دائم الظهور في الجوال، وقائمة HTML، وخطوات استخدام فعلية، وحدود واضحة قبل البدء. لا حاجة لتسجيل جديد أو خطوات زائدة قبل وظيفة التطبيق.

المظهر الليلي يستخدم موفر المشروع الموجود ومفتاحه نفسه، ولا توجد مكتبة أو خدمة إضافية. CSS الجديد محصور في صفحات العرض العام، وصفحات اللوحة وSidebar وProviders لم تتغير. أضيفت أسماء لعناصر التحكم، وتركيز مرئي ووصلة تخطي وحالة تحميل للدخول، مع دعم تقليل الحركة.

البريدان `support@wasiyati.app` و`security@wasiyati.app` محفوظان كنصين مؤقتين غير مفعّلين، بناءً على تأكيد المالك عدم وجود نطاق أو بريد للدعم. لا نموذج يدّعي إرسال الطلبات ولا وعد رد خلال مدة معينة.

### حدود التحقق التي بقيت

تشغيل `next start` المحلي نجح في بدء الخادم، لكن طلب الرئيسية أعاد 500 بسبب `NEXTAUTH_SECRET` المفقود. لم نضف قيمة وهمية ولم نغير متغيرات البيئة. فحوص HTTP والمتصفح أجريت على `next dev`، وليس اختبار إنتاج كامل. البناء النهائي نجح مستقلاً، وأُوقف خادم المعاينة بعد الاختبار.

أثناء اختبار تحويلات الصفحات الخاصة ظهر في سجل الخادم خطأ قراءة `session.user` من جلسة null في `/dashboard` و`/dashboard/messages` و`/dashboard/settings`، رغم رجوع 307 إلى الدخول. هذه الملفات مطابقة للأصل، ولم يُنفذ تعديل على المصادقة أو منطق اللوحة لإخفاء المشكلة.

لم تُختبر كتابة الرسائل أو تعديلها أو حذفها بحساب حقيقي، أو Google OAuth، أو إرسال بريد، أو الحفظ والحذف في Drive، أو cron أو تأكيد الشاهد الفعلي، لغياب الاعتمادات وحساب الاختبار وقاعدة مخصصة. لا تدّعي هذه المهمة نجاح تلك العمليات. دليل بقاء المنطق هو مقارنة المصدر والبناء والتحويلات، وليس E2E متصلاً بالخدمات.

لم يُشغّل lint تفاعلي بإعداد جديد، ولم يُعدّل إعداد lint الأصلي. محاولة فحص أنواع بالتزامن مع إعادة بناء `.next` واجهت ملفات مولدة مؤقتة مفقودة؛ الفحص النهائي أُعيد بعد اكتمال البناء ونجح.

## 6. توصيات مؤجلة خارج النطاق

1. اختبار قبول على بيئة منفصلة مع Google وحسابين وقاعدة اختبار وResend/Drive قبل النشر. تأكيد إعداد الفرع المنشور؛ الموقع الحالي حوّل زيارة الجذر إلى الدخول أثناء المعاينة.
2. معالجة قراءة جلسة null في صفحات اللوحة قبل طلب `user`، ضمن مهمة مصادقة/منطق منفصلة.
3. مراجعة محرك الإرسال: `sendEmail` يعيد false عند الفشل، وبعض الاستدعاءات لا تبني الحالة عليه. SMS وWhatsApp يسجلان SENT دون مزود. يلزم فصل محاولة الإرسال عن التسليم الفعلي قبل تسويق القنوات أو الموثوقية.
4. مراجعة المنطقة الزمنية والجدولة وحالات إعادة المحاولة. `vercel.json` الحالي كل 30 دقيقة، خلافاً لبعض الوثائق التي تقول يومياً؛ تأكيد تشغيل cron خارجياً مطلوب.
5. استكمال مساري `/api/checkin` و`/api/keyholder/deny` المشار إليهما في قوالب البريد وغير الموجودين حالياً، بمراجعة أمنية واختبارات. عولجت فقط وجهات العرض المفقودة التي لا تحتاج تغيير API.
6. استكمال حذف الحساب والترقية والدفع إذا أراد المالك، مع سياسة واضحة للنسخ الخارجية والاحتفاظ. لم تُضف وظائف أو خدمات من هذا النوع.
7. اعتماد نطاق وبريد دعم وخصوصية وأمان عامل، وهوية مشغّل وشروط نهائية ومدد احتفاظ. تظل العناوين الحالية غير مفعّلة والمسودة غير معتمدة.
8. مراجعة تحديثات الاعتماديات وتحذيرات npm وملف القفل في تغيير منفصل، مع اختبارات للمنطق والخدمات. لم تُحدّث الإصدارات ضمن هذه المهمة.

## إعادة التحقق

ثبّت الاعتماديات الموجودة بوضع التوافق، ثم شغّل البناء وفحص الأنواع بالتتابع. لا تستخدم أوامر Prisma الخاصة بالمخطط لهذه المهمة.

```text
npm ci --legacy-peer-deps --no-audit --no-fund
npm run build
node node_modules/typescript/bin/tsc --noEmit --pretty false
npm run dev -- --hostname 127.0.0.1 --port 3000
```

في طرفية ثانية، بعد جاهزية المعاينة:

```text
node scripts/audit-public.mjs http://127.0.0.1:3000
```

أوقف خادم المعاينة بعد التحقق. لا يبدأ هذا التسلسل عملية نشر أو كتابة بقاعدة البيانات، ولا يتطلب تعديل أسرار المشروع لتدقيق الصفحات العامة في وضع التطوير.
